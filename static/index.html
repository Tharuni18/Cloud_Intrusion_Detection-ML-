Safe connection pattern

Keep provider credentials and the service token on a trusted server.

  1. 1
    Set up a provider-side relay

    Use your cloud's event delivery service or SIEM to send selected flow features or native findings to your backend.

  2. 2
    Normalize and validate

    For ML scoring, derive the exact schema from /v1/schema. If a source lacks a measurement, do not invent it; choose a model trained for that source.

  3. 3
    Forward over TLS

    Keep the bearer token out of browser code. Bind the API remotely only with TLS, and rotate credentials after exposure.

Not connected to a cloud account

No AWS, Azure, or Google credentials are configured in this project. Provider-side delivery rules and least-privilege permissions still need to be set up in your account.

ABOUT THE PROJECT

Detection with clear limits.

CloudIDS is an experimental intrusion-detection project built for evaluation and analyst review.

What it does

Random Forest and XGBoost classify patterns learned from labelled network flows. A benign-trained autoencoder and K-means model flag flows that differ from learned benign patterns. A hybrid combines those signals.

What it does not do

It does not independently collect packets, prove a breach, block traffic, or connect to a cloud provider. Native cloud findings are ingested and displayed separately from ML predictions.

Dataset context

The current benchmark is UNSW-NB15 with a class cap and an attack-heavy held-out test mix. Your production results can differ substantially. Validate on representative telemetry before relying on it.

Recommended use

Use alerts as investigation leads, measure false alarms with your own benign traffic, protect the event database, and connect providers through a least-privilege relay.
